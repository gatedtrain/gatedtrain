[unpublished references and recipe paths](development.md#unpublished-references).

- **Interim rules:** G-1 to G-20 (G-3 revised on 2026-11-09) and the maintainers' decisions D-1 to D-5 are applied as written. F-1, F-2, F-3, F-6 and F-13 are resolved by those rules; F-5 stays open.
- **Short forms:** `04` is `04-workflow-and-composition.md` and `05` is `05-evaluation-and-lineage.md`.

## Resolved by interim rules (round 2, 2026-11-09)

- **F-1. What sets `underpowered`.** Resolved by G-3 (revised): `underpowered` is true when n < n_required or achieved power < the registered power (04:102, 05:82). The code already did this; the comments now cite the revised rule.
- **F-2. Equivalence has no power or required n.** Resolved by G-12: when achieved power cannot be computed, `underpowered` is true, so an equivalence non-rejection is INCONCLUSIVE, never FAIL (05:82). `achieved_power` and `plan.n_required` stay null. The design still lacks the TOST formula (05 section 3.6); the proposed design change stands: "05 §3.6: add the TOST power and sample-size formula so equivalence gates can report achieved power."
- **F-3. Achieved power when the observed SD is 0.** Resolved by G-13: the limit 1.0 is kept and `sd_zero: true` is printed in the JSON and text reports. The lr = 0 control on 500 prompts is FAIL with `sd_zero: true`; on 30 prompts it is INCONCLUSIVE (plan underpowered).
- **F-6. Tier B data from Hugging Face.** Resolved by G-14: the runbook exports the training split to local shard files under a manifest before the first run, and falls back to precision `stage` (05:348) without the export. The skeleton has no writer for `stage`-precision edges; the runbook says to record that edge by hand.
- **F-13. Missing validation metric on Tier B.** Closed: at `4f39fd8` NeMo RL warns and still saves when no validation metric was collected (`grpo_sync.py:1356-1366`, save at `:1378-1386`, verified in the pinned clone).

## Open: needs a maintainers' or design-owner decision

### F-4. Interval method: the design says BCa

- 05:105 names the prompt-clustered bootstrap with 10,000 replicates, BCa. The code computes BCa (bias correction with mid-rank ties, jackknife acceleration).
- The report records `interval.method = "cluster_bootstrap"` (the 05 clause vocabulary, 05:78) and `interval.bootstrap.variant = "bca"`.

### F-5. G-4 applied beyond the listed fields

- G-4 names α, power and margin. The code also refuses (REG-FIELD) when the spec's gate type, `metric`, `mde` (→ `planning_effect`), `cluster_by` (→ `unit`), `seeds` (→ number of `eval_seeds`), `sampler` (→ `sampler.name`) or `evaluator` (→ `evaluators[].id`) differs from the registration. These are the 04:98 mapped fields plus the sampler and evaluator that 05:142 puts in the registration.
- The registration's `workflow` and `gate` names are **not** compared with the spec. The demo controls `spec-no-train.yaml` and `spec-bad-train.yaml` reuse `registration.yaml`, which names the workflow `skeleton-addition-demo`, so such a check would refuse the demo fixtures. Whether one registration may serve several workflows is a design question.
- `test_spec_errors.TestRegistrationIsAuthoritative` now covers G-4 through `gatedtrain run` for alpha, power, mde, margin, type, seeds, sampler and evaluator.

### F-7. Registration contents enforced as an interpretation

- `analysis_code_version` must equal the running code (`gatedtrain 0.3.0`); otherwise REG-FIELD. 05:142 lists the version in the registration but states no mismatch rule.
- `multiplicity` must be `{plan: single_gate, family: null}`; `sigma_plan` must be `ucb80` or `fixed`; `unit` must be `prompt`; `interval` must be `cluster_bootstrap`. These are skeleton limits, refused with REG-FIELD rather than ignored.

## Recorded: naming choices and stand-in scope

- **F-8. Rule IDs beyond tests/README.md section 3.** Errors that are not spec or registration rules get their own IDs: `TRAINER-CONFIG` (stand-in config), `ARTIFACT-HASH` (a pinned non-registration artifact differs from its pin, 04:80), `WARMUP-OUT` (existing `--out`), `IMPACT-TARGET` (malformed hash or missing path). Grammar keys the skeleton cannot honor (`rewards`, `labels`, a lone `alpha_family`, `gate.threshold`, `gate.human`, `test.bar`, `test.type`) are refused with `SPEC-SHAPE` instead of being ignored.
- **F-9. The demo stage runs 20 epochs.** The tuned stage consumes 100,000 samples (2,000 steps × 50) from 5,000 rows, so every saved checkpoint (steps 500 to 2,000) possibly consumed every training shard. The E2E impact test still checks the rule `last_step_included ≥ first_step(S)`, but on the demo it cannot tell checkpoints apart. The ledger unit test covers a partial mapping. Fewer steps did not train the stand-in well enough (about 6% exact match after 300 steps of 25).
- **F-10. A failed run leaves its directory.** A run that fails after its directory is created leaves a partial directory. It is never reused or overwritten, but no failure marker is written.
- **F-11. Stand-in tuning (Tier A only).** Warm-up 1,500 steps × 50 on the 1,000-row warm-up shard gives a baseline of about 24% exact match; the stage (2,000 steps × 50, lr 0.003) gives about 84%; training on shuffled labels gives about 1%. `trainer-lr0.yaml` keeps lr = 0.
- **F-12. Common random numbers in the stand-in evaluator.** Repeat r of every prompt draws its uniforms from `eval_seeds[r]`, one per (prompt, token position), and samples by inverting the model's CDF. Identical models give identical samples (the lr = 0 control shows Δ̂ = 0 exactly), and similar models give coupled samples (05:97).
- **F-14. R9-OI-1.** `sbatch --no-requeue` prevents only Slurm's own requeue. An administrator or an automated health-check service can still requeue; a second attempt would break the ledger writer's one-attempt assumption (05 section 12.4). Noted in the runbook; `tierb-collect` refuses a second `exp_*` directory.

## Design revision 10 alignment (tests/README.md section 11.15, R10A-1 to R10A-16)

- **R10A-1 (R10-3, supersedes G-3's equivalence part and G-12; resolves F-2).** `plan()` gives the TOST required n (05 §3.6) and `evaluate()` the TOST achieved power at the planning effect. A powered equivalence non-rejection is now FAIL; an underpowered one stays INCONCLUSIVE.
- **R10A-2 (R10-5, supersedes G-6).** `evaluators[0].manifest_hash` null or absent is refused (`REG-FIELD`); the fix line names the hash the prototype resolves: the Tier B identity hash (F-20, decision D-4), or for Tier A the stand-in identity hash (`runner.stub_evaluator_hash`, the hashes of the stub evaluator, model and task code). Every demo registration now carries its resolved hash. At run time a differing registered hash makes the gate MISSING with reason `evaluator_hash_mismatch`; the report gives `evaluator_hash` and `evaluator_hash_registered`. Changing the stub code changes the Tier A hash, so the demo registrations must then be re-resolved and the specs re-pinned.
- **R10A-3 (R10-8, supersedes G-18's refusal).** `pairing.max_unpaired` is an integer count or a fraction in [0, 1) of the 2|E| expected items, default 0. Above it the gate is MISSING (`missing_above_bound`), with `missing_baseline` and `missing_candidate` reported; `tierb-collect` writes the run instead of refusing with `TIERB-PAIRING`. `TIERB-PROMPTS` (a) now compares the union of both arms' problems with the held-out set.
- **R10A-4 (R10-9).** Optional `amends: sha256:<hex>` and `post_hoc: <bool>`; the report gives `registration_amends` and `post_hoc`. With `post_hoc: true` only a PASS changes: it becomes INCONCLUSIVE with reason `post_hoc` (maintainers' decision 2026-11-11); FAIL, INCONCLUSIVE and MISSING stay as they are. The prototype learns that an amendment followed candidate results only from the author's `post_hoc` value.
- **R10A-5 (R10-10).** `min_paired` (integer >= 1, default 10). Fewer pairs is INCONCLUSIVE (`min_paired`); a zero-width interval (n < 2 or SD 0) is INCONCLUSIVE (`zero_width_interval`) whatever its limiting power; the G-13 power limit and `sd_zero` stay.
- **R10A-6 (R10-7, supersedes G-8).** The spec's `test.alpha`, `power`, `mde` and `margin` are optional; the registration is authoritative and must carry `clause.alpha`. A spec value that differs is still refused (G-4).
- **R10A-7 (review finding 7).** New rule `TIERB-DATA` on the run's saved `data` section: `shuffle` must be `false`, `data.train` one dataset (a mapping or the one-element list NeMo RL saves), its `data_path` `<dir>/<export dir name>/train.jsonl`, and `split_validation_size` 0 (absent means 0, the `ResponseDataset` default, response_dataset.py:50 at 4f39fd8).
- **R10A-8 (review finding 8).** `k_actual` gives the [min, max] repeats per prompt of each arm; a maximum other than the registered K, or a repeat outside range(K), is MISSING (`k_mismatch`); a record whose `metadata.eval_seed` differs from `eval_seeds[repeat]` is MISSING (`seed_mismatch`). Tier B keeps each record's `metadata` when it reads `scorer_rewards`.
- **R10A-9 (review finding 9).** `gatedtrain impact` prints `counts: {orphaned, superseded}` (JSON) and `orphaned: <n>, superseded: <m>` (text). Orphaned records (after the last committed cut, one per (step, shard)) are kept in `lineage/orphaned.parquet`, outside the ledger, so they still enter no rollup; superseded is 0 (one attempt, one segment). (Later, EXT-RES-5: a resumed external run's ledger, consumption schema 1.1, also holds its orphaned records with `status: "orphaned"`; every rollup reads kept rows only.)
- **R10A-10 (review finding 10).** `p_value` with `p_value_method: bca_inversion`: the one-sided p for H0: Delta <= delta_sup (superiority) or Delta <= -delta (non-inferiority) inverts the BCa lower bound on the same bootstrap draws; equivalence reports the TOST p. Null for a zero-width interval or no pairs. The decision still comes from the interval.
- **R10A-11 (review finding 11).** `tierb-collect --nemo-rl-modified yes|no --image-build-notes TEXT`; the lockfile's `backend.trainer` records `nemo_rl_modified` (`"unknown"` without the flag) and `image_build_notes`.
- **Status reasons.** `status_reasons` lists `no_pairs`, `missing_above_bound`, `k_mismatch`, `seed_mismatch`, `evaluator_hash_mismatch` (MISSING) and `min_paired`, `zero_width_interval`, `post_hoc`, `underpowered` (INCONCLUSIVE); MISSING takes precedence over INCONCLUSIVE within a clause. All reasons that apply are listed, so a MISSING result may also name INCONCLUSIVE reasons; `underpowered` is listed only for a non-rejection.
- **R10A-14 (review follow-up MEDIUM-1): zero width up to float noise.** 05 §3.6 (05:156) makes a zero-width interval (σ̂_d = 0) INCONCLUSIVE. The prototype reads "σ̂_d = 0" as max(d) − min(d) ≤ 1e-12 · max(1, |mean(d)|) on the per-prompt differences (and n < 2), an implementation choice not in the design: per-prompt means of K binary rewards can equal 1/3 computed two ways (0.3333333333333333 and 0.33333333333333337, SD 9.8e-17), which exact `std() == 0` treated as a real interval. One function, `gates._zero_width`, now decides the zero-width interval (`bca_interval`), the null p-value (`bca_p_value`), `sd_zero`, the G-13 power limit and the `zero_width_interval` reason, so they always agree. With n = 1, `sd_zero` stays false (no SD) as before.
- **R10A-16 (review follow-up LOW-1): `p_value_at_floor`.** A prototype report field, not in the 05 §3.8 report list. It is true when the bootstrap tail behind the reported one-sided p is empty: G(null) clipped up to 1/(B+1) for H0: Δ ≤ null, or G(δ) clipped down to B/(B+1) for the upper TOST side; for equivalence the side that gives the reported maximum decides. The p-value is then a bound set by B, not an estimate (the real long run reported 8.54e-05 this way), and the text line reads `p_value: <= <p> (bca_inversion)`. A clip toward p ≈ 1 (a ceiling) and a null p-value give false.
- **p-value and interval at the boundary.** On lattice or binary differences the p-value and the interval verdict can disagree right at the boundary: G counts bootstrap ties at the null half, while the interval ends come from interpolated bootstrap quantiles, so p < α with a lower bound equal to the null (or the reverse) is possible. The interval decides the status and the p-value is reported only, which is conservative in the case that matters (p < α while the interval does not reject gives no PASS); the gaps are within the quantile-interpolation step of about 1/B.
- **Equivalence MDE in `plan()`.** For equivalence `plan()` still reports `mde` with the one-sided formula (z_{1−α} + z_power) σ √(DE / n) (05:124). It is display-only: `n_required` uses the TOST formula (R10A-1) and the verdict comes from the interval, so neither depends on it.

## Design revision 11 alignment (tests/README.md section 11.16, R11A-1 to R11A-22; design revision 13 notes)

## Design revisions 12 and 13: constraint clauses and blocking judges (tests/README.md section 11.17, R12A-1 to R12A-17)

- **Library only.** New module `gatedtrain/constraints.py` (naming choices): `clopper_pearson_upper`, `threshold_power`, `binomial_n_required`, `constraint_set_hash`, `violation_indicators`, `judge_qualification`, `evaluate_constraint`, `check_registration`; `report.constraint_report`; `gates.combine` unchanged (a constraint result is one more clause in `and`). `run` and the Tier B commands refuse a constraint registration (`REG-CONSTRAINT registration.clause.constraint_set`, "not wired"): wiring, CLI text and multiplicity stay out of scope (section 11.17 "Scope"). The gate reads recorded verdicts only (MULTIMODAL-SPEC MM-C1 to MM-C4); no code path calls a judge or opens a socket.
- **R12A-1, R12A-2 (R12-1, R12-4): registration.** A clause with `constraint_set` is a constraint clause: threshold (`type: superiority` with `bar`, P1) or `non_inferiority` (with `margin`); `direction: lower_is_better`; `interval: clopper_pearson` or `clopper_pearson_discordant`; no `sigma_plan` or `sigma_pilot` (P2); `planning_effect` in (0, `bar`] or (0, `margin`]. The registration holds `constraint_set` (id equal to the clause's; numbered constraints with one tool or judge checker; judges with their scorer fields; canaries) and, with judges, `judge_qualification` (P5). A `constraint_set` or `judge_qualification` without a constraint clause is refused; `bar` outside a constraint clause is refused (`REG-FIELD`). A spec `gate.threshold` maps to `superiority` and `test.constraint_set` must equal the clause's (G-4); `run` itself still accepts only the three paired gate types.
- **R12A-3: scorer hash.** `constraint_set_hash` is the RFC 8785 canonical JSON SHA-256 of the whole set (P9); `evaluators[0].manifest_hash` must equal it, and an arm run with another set is MISSING `evaluator_hash_mismatch`.
- **R12A-4 to R12A-7: statistics.** Records are screened by `gates._screen_arm` (range [0, 1]); a score other than 0 or 1 is `out_of_range` (P8), an error its class. v_i is the maximum over the usable repeats (non-inferiority: those usable in both arms). Threshold: exact Clopper-Pearson upper bound of k/n below `bar`, p = P(X ≤ k; n, `bar`), binomial power at `bar − planning_effect`. Non-inferiority (R13-1): bound of c/n below δ, p = P(X ≤ c; n, δ); b, c, `delta_hat` = (b − c)/n and `difference` = (c − b)/n reported. `sd_zero` when all per-item values (differences) are equal; the bound keeps positive width, so it is never the zero-width INCONCLUSIVE. `underpowered` when power is below target, n below `n_required`, or the planning rate is outside [0, bound) (power not computable). MISSING precedes INCONCLUSIVE; `max_unpaired` as a fraction is taken over the expected items of all arms (one arm for the threshold form).
- **R13-2 and prototype choice P4 (revised).** Power and n of the non-inferiority form are binomial as in the threshold form with δ for `bar`. 05 §3.9 says "the registered planning rate of c/n" without naming a field; the prototype reads it as `margin − planning_effect`, the same construction as the threshold form's planning violation rate, so no clause field is added. To confirm with the design owner (the alternative is a separate clause field holding the rate).
- **R12A-9 to R12A-14 (R12-3, R12-5, R13-3, R13-4): judges.** `judge_qualification` returns `can_block_alone`, `failed` (`a_validity` … `e_external`), the miss and false-alarm rates and their Clopper-Pearson upper bounds at the clause's α (R13-3), and the identity fields the report needs. On a blocking clause each failing input is `REG-JUDGE` on its own field and the run-time clause is MISSING `judge_not_qualified`; on a non-blocking clause the judge is supporting (no `REG-JUDGE`). A missing egress approval of an external judge is `REG-EGRESS` blocking or not, and MISSING `egress_unapproved` at run time. Per-batch canaries (registered set; MISSING `canary_absent` / `canary_missed`) apply only to a blocking clause (R13-4); a supporting judge's batches are still summarised in `canaries` (with `required: false` and `by_arm`).
- **Report (R12A-16).** `constraint_report` copies the section 11.17 keys from the result; for the non-inferiority form the top-level canary lists concatenate both arms and `evaluate_constraint`'s `canaries.by_arm` attributes them.
- **Not done (deferred).** Wiring into `run`, `tierb-collect` and `ext-collect`, the CLI text, reading `items.jsonl` / `judge_batches.jsonl` / `eval_meta.json` from disk (MM-C1 to MM-C3; only the in-memory MM-C4 form exists), counting the constraint clause in m (05 §3.5), 06 B26 conformance canaries of supporting judges, and computing tiers and independence from lineage (P5 declares them). (A record in two batches of one judge is now MISSING `malformed_batch`, R12A-21.)

## Python 3.12: lenient `realpath` (found by the first CI dry run, 2026-11-19)

- **`ext-launch` and `ext-collect` crashed on 3.12 where they must refuse.** `os.path.realpath` without `strict`
  raises `PermissionError` on Python 3.12 when a path component is a symbolic link the user may not read
  (`/proc/1/root`, `/proc/1/cwd`), where 3.13 keeps the component and goes on. The lenient resolution of a mount
  source (`_real`, used by the socket rule, EXT-40, before the strict EXT-51 check) therefore raised, and the CLI
  exited 1 with a traceback instead of 3 with the refusal (8 subtests of `test_ext_review2` on 3.12). No mount was
  ever accepted. `Path.resolve()` (not strict) has the same problem, in the SDK's `bound_mounts` and the diffusers
  family's mount checks among others. `gatedtrain.paths` now holds `realpath` and `resolve`, Python 3.13's lenient
  `realpath` ported line for line, and every lenient resolution of a path from a request, a launch record or a run
  output (`ext/` and `families/`) uses them; paths the user names on the command line keep `Path.resolve()`. On 3.13
  the results are the standard library's; on 3.12 they differ only after a symbolic link loop, where 3.12 stops and
  3.13 resolves the rest (`tests/test_paths.py`: 2,000 random paths over a tree of link chains, a loop and `..`; the
  `/proc` cases where the link is not readable).

## Review of the 3.12 path fix (2026-11-19)

A review of the lenient `realpath` change (previous section) reproduced each finding below with a script before the
fix; the reproductions are now tests (`tests/test_path_review.py`, tests/README.md section 11.34).

- **S1, S2, S5 (`output_ref` resolved by path).** `arm._output_ref_problem` checked that the lenient `realpath` of
  `<arm>/<path>` lay inside the arm, then hashed and copied by path. Where the lexical resolution exceeds `PATH_MAX`
  the lenient `realpath` keeps the rest of the path unresolved, so a link chain (`a` and `a/b` each a 2.5 KB relative
  chain, `b/leak` a link to a host file; S2) or a relative arm under a long cwd (S1) passed the check while the kernel
  opened the host file, and `ext-collect` copied it into the run. An absent path longer than `PATH_MAX` raised
  `OSError` (ENAMETOOLONG) out of the check (S5). **Maintainers' decision (2026-11-19): an `output_ref` path contains
  no symbolic link at all** (hard links are allowed; MULTIMODAL-SPEC MM-1). `arm.open_output_ref` opens the arm
  directory, then each component under the previous descriptor with `O_NOFOLLOW` (`O_DIRECTORY` for directories,
  `O_NONBLOCK` for the file, which must be regular by `fstat`) and hashes from that descriptor. Messages: `output_ref
  path '<p>' contains a symbolic link ('<component>'; MM-1 allows none)`, `output_ref file '<p>' is absent`, `... is
  not a regular file`, `... cannot be opened (<errno name>)`, `... cannot be opened: the arm directory cannot be
  (<errno name>)`; `leaves the arm` (absolute or `..`, checked lexically) and `differs from its sha256` are unchanged.
- **Copy after the check.** `ext-collect` (both copy sites) and `ext-merge-eval` copied `output_ref` files with
  `shutil.copyfile` by path after the checks, so a file swapped in between was copied. `arm.copy_output_ref` copies
  from the descriptor of the same walk, hashing while it copies; a link or a different hash is refused (EXT-ARM on the
  arm's flag, `(changed after it was checked)`), and the partial output is removed as for any refusal.
- **Arm files under a long path.** `read_meta`, `read_lines` and `provenance_problems` used `Path.is_file()` and
  `Path.exists()`, which raise ENAMETOOLONG (and EACCES) on Python 3.12; they now report `<file> cannot be read
  (<errno name>)`.
- **S3 (link loop on 3.12).** `Path.resolve()` raises `RuntimeError` for a symbolic link loop on Python 3.12. The
  spec's `file:` URIs and the spec path (`spec.py`), the manifest `root` (`canonical.manifest_document`) and
  `warmup --out` (`cli.py`) now resolve with `gatedtrain.paths`, so a loop is a refusal; this replaces "paths the user
  names on the command line keep `Path.resolve()`" of the previous section.
- **S4 (duplicate arms).** With several clauses, `ext-collect` told arms apart by their resolved path string, which
  differs for one directory reached by two paths when resolution stops early (a path past `PATH_MAX`). Arms are now
  keyed by `(st_dev, st_ino)` of the directory; an arm that cannot be inspected is refused.
- **S6 (EXT-113).** `_in_tree` judged the interpreter's host file by the lenient `realpath`, so a loop, a missing
  file or an unreadable link below a tree's lexical path counted as inside it. It now uses the strict `realpath`, and
  a path that does not resolve is in no tree.
- **C1 (fixtures tied to uid 1000).** The launch fixtures named `user: "1000:1000"`, and EXT-63 requires the output
  directory, which the tests create, to be owned by the container's uid, so the suite passed only as uid 1000 and CI
  ran it through `sudo -u '#1000'`. The fixtures now use `_ext.container_user()` (the running uid and its primary
  group; the golden request and command carry a `<user>` placeholder filled at load time); the tests skip with a
  reason as root, for a uid without a user database entry, or when that primary group owns a Docker socket.
  `.github/workflows/test.yml` runs the suite as the runner user.
- **T1, T2 (`test_paths` oracle).** On 3.12 the random comparison left every path through the loop out, and no case
  had a regular file in the middle, so a 3.12-style loop (stop and keep the rest), an undetected loop (a hang) and
  catching only `FileNotFoundError` and `PermissionError` (ENOTDIR) survived. `test_fixed_values` pins values that
  3.12 and 3.13 both give (`loop1/x`, `loop1/../a`, `a/f/x`, `a/f/..`, ...), and a `SIGALRM` watchdog fails a test
  that does not end in 30 s. The review's mutants (edits of `paths.realpath`) are killed on 3.12 and 3.13: M1a
  drops the loop check (resolution never ends), M1b stops at a loop and keeps the rest (3.12's behaviour), M2b
  catches only `FileNotFoundError` and `PermissionError` (ENOTDIR below a regular file raises).
- **T3.** A loop as an `output_ref` component is a case of `test_path_review` (refused as a symbolic link).
- **T4.** A loop and an unreadable link (`/proc/1/root`) at the launch record's `output_dir` against `--stage-out`,
  the SDK's `bound_mounts` and the diffusers family's mount checks give a mismatch or no binding, never a traceback.
- **T5.** `test_paths.test_unreadable_link_is_kept` skips where `/proc/1/root` is readable (as root); accepted.

## Review of PR 2 (2026-11-19)

Four reviews and a verifier of the change above (gatedtrain PR 2) found that the arm's own files and the provenance
sources were still read by path. Each finding was reproduced before the fix and is now a test
(`tests/test_arm_reads.py`, `test_r18_clauses.CollectTwoClauses`, tests/README.md section 11.34). The ids are
prefixed `PR2-` here, since the review of the 3.12 path fix used C1 too; test docstrings cite them unprefixed.

- **PR2-A1 (blocking).** `ext-collect` copied `items.jsonl`, `eval_meta.json` and `merge.json` into the run by path
  (`is_file`, `shutil.copyfile`, following links) after checking them, so a container still writing its arm could
  swap one for a link to a host file between the checks and the copy, and the run's `items.jsonl` could differ
  from the records gated. New module `ext/armfs.py`: `ArmSnapshot.read` opens the arm directory once and reads the
  three files once each (without following links, at most 1 GiB) with their SHA-256; `read_meta`, `read_lines`,
  `provenance_problems` and the EXT-52 re-derivation parse those bytes, and `ext-collect` writes them into the run.
- **PR2-A2.** `provenance_problems` hashed any host path named in `merge.json` (`sources[].path`, `run_dir`), printed
  the hash (an oracle for host files) and blocked on a FIFO. Sources must now be absolute paths in normal form
  under the sources root (the host's output root, or the new `ext-collect --sources-root`; MULTIMODAL-SPEC MM-5),
  are reached from the root's descriptor without following links and read as arm files; a mismatch says
  `differs from the recorded hash`, and a source outside the root is refused (`provenance cannot be checked`).
  `ext-merge-eval` and `ext-from-nel` record `os.path.abspath` of a source (normal form).
- **PR2-A3.** `read_meta` followed links and echoed the content of the file it read (unknown keys, the schema value);
  a stat-then-read race and a FIFO hang remained. A link is now refused before anything is read, so only the arm's
  own regular file is ever parsed.
- **PR2-A4.** The output walk opened the last component before checking its type (a device node opened by the
  collecting user). Every component is now opened with `O_PATH` (intermediates `O_PATH | O_DIRECTORY |
  O_NOFOLLOW`); only a regular file is reopened for reading (`/proc/self/fd`, `O_NOCTTY`) and must be the same

- **PR2-A5.** `ext-merge-eval` told outputs apart by the raw path string (`outputs/x.txt` and `outputs/./x.txt`, the

- **PR2-A6.** A NUL or a lone surrogate in an output path raised `ValueError` or `UnicodeEncodeError`; now `contains a

- **PR2-B1.** An intermediate directory with mode 0o111 (search only) was refused (EACCES); `O_PATH` walks it on
  Linux. Without `O_PATH` (macOS) it is still refused, and a file swapped for a FIFO or device between the type check

- **PR2-B2.** tests/README.md EXT-45 now says any link is refused.
- **PR2-B3.** A read error of an output during the copy was reported as a failed write of `--runs-root`; it is an

- **PR2-B4.** The duplicate-arm key is the opened directory's identity from the snapshot; an arm that does not open

- **PR2-C1, PR2-C2.** The S4 test now includes an alias past `PATH_MAX` (a working directory deeper than `PATH_MAX`, `arm`

## The CPU demo across machines (found by CI, 2026-11-20)

- **The demo's gate depended on the runner's CPU.** The stand-ins train on one thread with deterministic algorithms,
  so a run repeats exactly on one machine, but PyTorch chooses CPU kernels by instruction set and MKL its BLAS code
  path. On GitHub runners the same commit and the same wheels gave PASS in one job and FAIL in another
  (`test_e2e_slow`: the warm-up baseline scored 0.833 there against 0.522 on the development host). Three code paths
  depend on the CPU: ATen's kernels, MKL's BLAS and oneDNN, which JIT-compiles kernels for the instruction set (the
  stand-ins' GELU ran as `eltwise jit:avx2` on the development host and on AVX-512 on a Xeon runner; a first fix that
  pinned only ATen and MKL still gave 0.745 there). The stand-ins now pin `ATEN_CPU_CAPABILITY=default` and
  `MKL_CBWR=COMPATIBLE` before torch is imported (`gatedtrain/stubs/__init__.py`; an operator's own setting wins) and
  turn oneDNN off (`model.configure_torch`); `runner.run` imports the stand-ins before torch. The CI workflow prints the
  runner's CPU model and instruction sets.
